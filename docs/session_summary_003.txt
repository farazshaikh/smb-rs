## KEY BUGS FIXED THIS SESSION
1. find encoder: final entry NextEntryOffset was never zeroed; DIRECTORY
   (0x102) layout lacked the four FILETIMEs; DOS size table mismatched.
2. Header2: SessionId is at 40..48 (36..44 was TreeId+half). TreeId @36.
3. SESSION_SETUP body: Flags/SecurityMode are SINGLE bytes; fixed part is 24;
   blob located by SecurityBufferOffset (both samba + impacket send it).
4. TREE_CONNECT response must stamp the NEW TreeId into the response header.
5. CREATE response FileId lives at offset 64 (after Reserved2), NOT at 8.
6. READ response DataOffset is header-ABSOLUTE (80), not body-relative (16).
7. Negotiate responses need SecurityBufferOffset = 128 when blob empty
   (samba checks secoff == 64 + masked body size).
8. Samba's initial negotiate uses the 3.1.1-style body: dialect array at
   offset 36/44 (after NegCtxOffset fields), not 28.
9. QUERY_DIRECTORY: clients repeat the pattern on continuation calls —
   only RESTART/REOPEN/SCAN flags (or missing state) may restart the enum,
   otherwise infinite loop.
10. Every non-SUCCESS status needs a generic ERROR body (StructureSize 9,
    padded to 8) — bare headers break client compound parsers.
11. FileAllInformation: embedded FSCC structs are 8-byte aligned inside the
    composite (Basic occupies 40 bytes incl. pad).

## KEY GOTCHAS
- cargo build at workspace root builds only meta pkg — always use
  `cargo build --release --workspace`.
- Buffer offsets in SMB2 bodies are ABSOLUTE from frame start (parsers here
  take the full frame; BODY const = 64).
- StructureSize odd values mean "+1 variable buffer"; samba masks to even
  and compares against bytes actually present.
- Response credits: grant 1 per request; echo CreditCharge from request.
- Compound replies: patch NextCommand of every non-final frame, 8-align.
- Guest/anonymous sessions have no signing key; authenticated ones MUST get
  signed responses whenever the request carried SMB2_FLAGS_SIGNED.
